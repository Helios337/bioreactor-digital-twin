# Project Agent Rules

These rules bind every agent working in this repository. They derive from the research brief and are non-negotiable.

## Research integrity

- Never fabricate a citation, result, numerical improvement, equation, data-availability claim or limitation.
- A paper title or abstract is not proof the full paper was read. Track abstract-only versus full-text access per source.
- Verify every DOI, author list, year, title and venue before citing. Record discrepancies instead of guessing.
- Every non-trivial scientific claim in the manuscript carries a citation.
- Separate established evidence, authors' interpretation, and reviewer proposal.
- Treat candidate gaps as hypotheses until citation chaining (references and cited-by) confirms them. No novelty claim before chaining.
- Keep input-distribution drift, sensor fault, prediction uncertainty, and unsafe control conceptually distinct.
- Never describe the proposed architecture as perfect, safe, or validated. Use proposed, reliability-oriented, to be evaluated.
- Tool output is evidence gathering, not scientific validation.

## Evidence and access vocabulary

- Access status per source: metadata-verified, abstract-read, full-text-read.
- Evidence level in the matrix: full-text, abstract, metadata.
- Cells without evidence are marked pending full text. They are never filled by inference.

## Terminology

- Penicillin-specific evidence requires a penicillin process and dataset. Transferable methods are labelled as transferable.
- IndPenSim data are simulated benchmark data, not plant measurements. State this wherever the benchmark is used.
- The community IndPenSim repository is not an authority. Goldrick 2015 and 2019 are the source of truth.

## File conventions

- One full sentence per line in long Markdown files.
- Plain hyphens, no em dashes.
- BibTeX entries come only from references/references.bib, generated by tools/build_bib.py from verified API fields.

## Scope guardrails

- Do not download the IndPenSim dataset during the review phase.
- Do not train models or claim experimental performance until the gated Track B phase is explicitly triggered.
- Do not install MCP servers or third-party skills without inspecting the source first. Keep API keys out of committed config.

## Workflow

1. Verify before citing (citation-verification skill).
2. Extract into the matrix (literature-review skill).
3. Write with claim-level citations and layer separation (scientific-writing skill).
4. Keep concept boundaries clean (bioprocess-control-review skill).
5. Commit atomically with descriptive messages.
